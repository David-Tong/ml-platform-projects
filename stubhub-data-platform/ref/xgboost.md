# XGBoost：树怎样成为价格回归模型

本文假设你已经理解机器学习中的特征、标签、训练集、测试集和回归任务，但没有接触过树模型与梯度提升。配套系统文档以 2019 年为背景，以下代码使用当时 XGBoost 0.90 的接口。

我们从你熟悉的回归函数开始，依次回答三个问题：

1. 一棵树怎样把特征变成预测价格？
2. 多棵树怎样组成一个回归模型？
3. XGBoost 怎样学习这些树？

全文使用同一组小数据手算，再用代码复现。所有价格与规则均为教学假设，单位为美元，不代表真实 StubHub 市场规律。

## 1. 回归模型是一种函数，树也是函数

预测价格时，我们要学习一个函数：

```text
predicted_price = F(x)
```

这里 `predicted_price` 表示预测价格，`x` 表示输入特征。全文使用普通文本公式：`*` 表示乘法，`^2` 表示平方，`sum(...)` 表示求和。


如果使用线性回归，可以写成：

```text
F(x) = b + w_1 * seat_level + w_2 * inventory
```

线性回归通过加权求和得到价格。回归树则通过条件判断，把输入分到一个区域，再输出这个区域对应的数值。

例如，这棵树本身就是一个价格回归模型：

```text
座位档次 < 2？
├─ 是 → 预测价格 110
└─ 否 → 预测价格 190
```

给它输入“座位档次 1、库存 200”，输出 110；输入“座位档次 2、库存 40”，输出 190。这棵树没有使用库存，因此同一档次的票都得到同样的预测。

它等价于分段常数函数：

```text
f(x) = 110  if seat_level < 2
f(x) = 190  if seat_level >= 2
```

**树的分支决定输入属于哪个区域，叶子保存该区域的输出数值。树通过这种方式表示一个回归函数。**

增加分支就能划出更多区域。例如先按座位档次分，再按库存分，同样的座位档次下就可以得到不同价格。

## 2. 一棵回归树怎样训练：学习切分条件与叶子值

使用以下四条训练记录：

| 样本 | 座位档次 `seat_level` | 库存 `inventory` | 成交价 `price` |
|---|---:|---:|---:|
| A | 1 | 200 | 100 |
| B | 1 | 40 | 120 |
| C | 2 | 200 | 180 |
| D | 2 | 40 | 200 |

这里的座位档次有明确顺序，不是任意票区 ID。

### 2.1 叶子输出怎样确定

先考虑普通回归树，采用平方误差，不加入额外正则项。

假如按照座位档次分成两个叶子：

- 左叶子包含 A、B，真实价格为 100、120。
- 右叶子包含 C、D，真实价格为 180、200。

每个叶子只能输出一个数。使叶子内平方误差之和最小的数，是该叶子中标签的平均值：

```text
w_L = (100 + 120) / 2 = 110
```

```text
w_R = (180 + 200) / 2 = 190
```

于是就学到了上一节的树。

### 2.2 为什么选这个切分条件

可以比较不同切分带来的平方误差之和。此处用 SSE 表示，不取平均。

| 方案 | 各组的预测值 | SSE |
|---|---|---:|
| 不切分，所有票一组 | 全部预测 150 | 6,800 |
| 按座位档次分两组 | 档次 1 预测 110，档次 2 预测 190 | 400 |
| 按库存分两组 | 库存 200 预测 140，库存 40 预测 160 | 6,400 |

例如，按档次分组后的误差为：

```text
(100 - 110)^2 + (120 - 110)^2 + (180 - 190)^2 + (200 - 190)^2 = 400
```

在这两个候选切分中，按座位档次切分更有效。

训练树的过程，就是不断尝试特征与阈值，选择能降低目标函数的切分，并确定叶子输出。通常使用逐步选择的方式，不会穷举所有完整树来寻找全局最优。

到这里，一棵树和回归的关系已经明确：**它学习的是一个分段常数的价格函数。**

## 3. 从一棵树到多棵树：把函数加起来

一棵较浅的树可能不够精细。梯度提升树采用加法模型：

```text
F_T(x) = b + eta * [f_1(x) + f_2(x) + ... + f_T(x)]
```

其中：

| 符号 | 含义 |
|---|---|
| `b` | 起始预测，例如训练价格的平均值 |
| `f_t(x)` | 第 `t` 棵树对输入 `x` 给出的修正值 |
| `eta` | 学习率，控制每轮采用多少修正 |
| `T` | 树的数量，本篇每轮增加一棵树 |

这里始终是在做价格回归，只是函数形式从“特征的线性组合”变成了“树函数的相加”。

多棵树不需要依次把结果传给下一棵树。预测时，每棵树都读取这张票的原始特征，各自输出数值，最后求和。它们的依赖发生在训练阶段：后一棵树要根据前面模型的表现学习修正。

## 4. 手算两轮：后面的树到底在学习什么

先采用平方误差，把学习率设为 1，暂时不加正则项。这样每轮修正全部加入，方便看清数字。

### 4.1 起点：所有记录都预测 150

训练价格平均值为：

```text
b = (100 + 120 + 180 + 200) / 4 = 150
```

每条记录的残差为真实价格减去当前预测：

| 样本 | 真实价格 | 起始预测 | 残差 |
|---|---:|---:|---:|
| A | 100 | 150 | -50 |
| B | 120 | 150 | -30 |
| C | 180 | 150 | +30 |
| D | 200 | 150 | +50 |

### 4.2 第 1 棵树：学习按座位档次修正

这次输入仍是座位档次与库存，但新树拟合的是残差。

按座位档次切分，两个叶子的残差平均值为：

```text
(-50 - 30) / 2 = -40
(30 + 50) / 2 = +40
```

所以第 1 棵树为：

```text
座位档次 < 2？
├─ 是 → 输出 -40
└─ 否 → 输出 +40
```

把它加到起始预测上：

| 样本 | 起始预测 | 第 1 棵树输出 | 更新后的预测 | 新残差 |
|---|---:|---:|---:|---:|
| A | 150 | -40 | 110 | -10 |
| B | 150 | -40 | 110 | +10 |
| C | 150 | +40 | 190 | -10 |
| D | 150 | +40 | 190 | +10 |

注意这两件事的区别：

- 单独训练价格回归树时，叶子可以直接输出价格 110、190。
- 在这个提升模型中，第 1 棵树输出的是修正 -40、+40；加上起始值 150 后，才得到价格 110、190。

### 4.3 第 2 棵树：学习剩下的库存差异

此时库存 200 的记录都还需要减 10，库存 40 的记录都还需要加 10。

第 2 棵树可以学成：

```text
库存 > 100？
├─ 是 → 输出 -10
└─ 否 → 输出 +10
```

100 是便于理解的分界；在这组数据上，其他把 40 和 200 分开的阈值也能得到相同训练分组，程序选出的具体阈值可能不同。

更新后：

| 样本 | 第 1 轮后的预测 | 第 2 棵树输出 | 最终预测 | 真实价格 |
|---|---:|---:|---:|---:|
| A | 110 | -10 | 100 | 100 |
| B | 110 | +10 | 120 | 120 |
| C | 190 | -10 | 180 | 180 |
| D | 190 | +10 | 200 | 200 |

这四条教学记录可以被两棵小树完全拟合。真实数据包含噪声，训练误差为零也不代表新数据上的效果好。

### 4.4 用这两棵树预测一张新票

新票是档次 2、库存 40。把同一个输入分别交给两棵树：

```text
起始预测                    150
第 1 棵树：档次 2 → 输出     +40
第 2 棵树：库存 40 → 输出    +10
最终预测                    200
```

预测时没有使用新票的真实成交价，使用的是训练阶段已经确定的分支和叶子值。

如果学习率改成 0.1，就要逐轮重新计算：第 1 轮只加入 10% 的修正，接着根据更新后的残差训练第 2 棵树。不能拿上面学习率为 1 时学到的所有树，统一乘 0.1 后当作重新训练的结果。

## 5. 为什么叫“梯度提升”：残差与梯度的联系

上一节的“拟合残差”来自平方误差的特殊性质。

把单样本损失写成：

```text
loss(y, F(x)) = 0.5 * (y - F(x))^2
```

对当前预测值求导（`d` 表示求导）：

```text
d(loss) / d(F(x)) = F(x) - y
```

负梯度就是（`residual` 表示残差）：

```text
-d(loss) / d(F(x)) = y - F(x) = residual
```

所以，对于平方误差，“让新树拟合残差”就是让新树近似损失下降的方向。

一般梯度提升把这个思路扩展到其他损失。分类等任务不应直接套用“真实标签减预测价格”的理解，需要根据相应损失计算梯度。

## 6. XGBoost 怎样在这个基础上训练树

XGBoost 是梯度提升的一种实现。本篇讨论默认的树模型；重点是它怎样用损失信息和正则项选择新树。

### 6.1 每轮使用梯度和二阶导数

记第 i 条记录的当前预测为 `predicted_i`，真实标签为 `y_i`，定义一阶导数 `g_i` 和二阶导数 `h_i`：

```text
g_i = d(loss(y_i, predicted_i)) / d(predicted_i)
h_i = d^2(loss(y_i, predicted_i)) / d(predicted_i)^2
```

对前面定义的半平方误差：

```text
g_i = predicted_i - y_i
h_i = 1
```

训练新树时，XGBoost 利用这些量形成二阶目标，并加入复杂度惩罚。

### 6.2 叶子输出：残差平均值如何推广

先只考虑 L2 叶子权重正则，令 L1 正则为零。对于落到同一个叶子的记录，定义：

```text
G = sum(g_i)
H = sum(h_i)
```

在这个设定下，叶子的最优未缩放输出 `w_best` 为：

```text
w_best = -G / (H + lambda)
```

其中 `lambda` 对应 `reg_lambda`。实际加入模型的修正还要乘学习率 `eta`。

回看第 1 轮左叶子，包含 A、B：

```text
G = (150 - 100) + (150 - 120) = 80
H = 2
```

- 如果 `lambda = 0`，叶子输出 `-80 / 2 = -40`，恰好是残差平均值。
- 如果 `lambda = 1`，叶子输出 `-80 / 3 = -26.67 (approximately)`，修正幅度被缩小。

这就把“新树拟合残差”的直觉与 XGBoost 的叶子计算连接起来了。其他正则设置或损失下，不能总把叶子值当成残差平均值。

### 6.3 分裂条件：比较目标改善了多少

把一个叶子切成左右两部分时，XGBoost 可用下面的增益比较候选切分：

```text
left_score   = G_L^2 / (H_L + lambda)
right_score  = G_R^2 / (H_R + lambda)
parent_score = (G_L + G_R)^2 / (H_L + H_R + lambda)

Gain = 0.5 * (left_score + right_score - parent_score) - gamma
```

这条式子表达的是：切分后左右两部分的收益，减去切分前的收益，再减去新增叶子的惩罚。`gamma` 对应 `gamma`，能阻止收益不足的切分。

在本例平方误差、无正则的情况下，这与前面通过平方误差选择切分的思路衔接起来。实际建树还会受深度、子节点权重等约束限制。

推导依据见 [XGBoost 官方树提升教程](https://xgboost.readthedocs.io/en/stable/tutorials/model.html)。

## 7. 用代码复现两棵树，直接查看叶子输出

这次使用与手算完全相同的四条记录。目的在于观察树结构和加法预测，因此不把这四条记录上的误差当成泛化能力评估。

在与历史依赖兼容的 Python 环境中安装；以下为 2019 年版本组合示例：

```powershell
python -m pip install xgboost==0.90 pandas==0.25.3 numpy==1.17.4
```

保存为 `xgboost_tree_demo.py` 后运行 `python xgboost_tree_demo.py`：

```python
import numpy as np
import pandas as pd
from xgboost import XGBRegressor

X = pd.DataFrame({
    "seat_level": [1, 1, 2, 2],
    "inventory": [200, 40, 200, 40],
})
y = np.array([100.0, 120.0, 180.0, 200.0])

# 刻意关闭正则与随机采样，并用学习率 1，对齐前面的手算。
# 这是结构演示的设置，实际业务应另行调参和评估。
model = XGBRegressor(
    objective="reg:linear",
    base_score=150.0,
    n_estimators=2,
    max_depth=1,
    learning_rate=1.0,
    reg_lambda=0.0,
    reg_alpha=0.0,
    gamma=0.0,
    min_child_weight=1.0,
    subsample=1.0,
    colsample_bytree=1.0,
    tree_method="exact",
    n_jobs=1,
    random_state=42,
)
model.fit(X, y)

# 打印每棵树的切分条件与叶子值。
for index, tree in enumerate(model.get_booster().get_dump()):
    print(f"\n第 {index + 1} 棵树：")
    print(tree)

# 旧版 ntree_limit=1 表示只使用第 1 棵树。
# 这里返回的预测已经包含起始值 base_score。
after_first_tree = model.predict(X, ntree_limit=1)
after_two_trees = model.predict(X)

result = X.copy()
result["actual_price"] = y
result["after_first_tree"] = after_first_tree
result["after_two_trees"] = after_two_trees
print(result.to_string(index=False))

# 验证前面手算得到的两轮预测。
np.testing.assert_allclose(after_first_tree, [110, 110, 190, 190])
np.testing.assert_allclose(after_two_trees, y)

new_ticket = pd.DataFrame({"seat_level": [2], "inventory": [40]})
print("新票预测：", model.predict(new_ticket)[0])
```

阅读树的文本输出时：

- `seat_level<...` 或 `inventory<...` 是切分条件。
- `yes`、`no` 指向不同分支的节点编号。
- `leaf=...` 是这棵树在该叶子的输出，本例就是修正值。
- 阈值可能与手画的树不同；关注它如何把训练记录分组，以及叶子修正是多少。

预期的两轮预测为：

| 样本 | 第 1 棵树加入后 | 第 2 棵树加入后 |
|---|---:|---:|
| A | 110 | 100 |
| B | 110 | 120 |
| C | 190 | 180 |
| D | 190 | 200 |

这些是由前面手算得到的预期值，代码里的断言用于核对它们。

## 8. 再看几个参数，就能联系到树的行为

| 参数 | 与前面例子的联系 |
|---|---|
| `base_score` | 本例明确设为起始预测 150 |
| `n_estimators` | 本例加几棵树；实际使用提前停止时是轮数上限 |
| `max_depth` | 每条路径最多几次切分；本例为 1，所以每棵树只问一个条件 |
| `learning_rate` | 每轮加入多少比例的新树修正，也会影响后续树的学习 |
| `reg_lambda` | 叶子值公式分母中的 L2 正则系数 |
| `gamma` | 对切分增加的复杂度收取惩罚 |
| `min_child_weight` | 子节点需要达到的 Hessian 权重之和，本例每个样本贡献 1 |

可以先把 `reg_lambda` 从 0 改成 1，观察叶子值和训练预测如何变化。改参数后应移除或更新示例中用于核对无正则手算结果的两个断言。

之后再尝试把学习率改成 0.1，观察两棵树为什么不再足以完成同样的修正。学习率较小时通常需要更多轮，但应根据验证集而非训练误差决定训练到什么时候。

## 9. 从结构演示走向真实价格模型

理解树怎样产生预测后，再增加真实业务所需的部分：

- 用历史数据训练，用验证集选择参数与停止轮次，最后用独立测试集评价。四条样本的精确拟合只说明计算过程，不说明业务效果。
- 按预测时点构造特征。预测后才发生的浏览、成交信息不能进入输入；时间切分还需考虑标签何时完整产生。
- 明确预测对象和标签关联规则。未成交的票没有成交价，不能把价格填成 0；仅用已成交记录训练，学到的是有成交标签群体中的价格关系。
- 预测金额不等于保证售出的挂牌建议，也不等于改变挂牌价的因果效果。“未来 7 天是否售出”需要另一套标签与损失。
- 同一挂牌的重复快照、同一活动的关联记录可能让评估过于乐观，需要根据实际预测场景处理切分。
